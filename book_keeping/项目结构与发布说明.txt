本地记账助手：项目结构与发布说明
================================

一、现在为什么分成这些文件夹
----------------------------

程序只维护一份业务代码，但不同操作系统不能共用原生运行环境：

程序源码/                  Mac 与 Windows 共用的唯一源码
运行环境/Mac-x64/          Mac Intel 的 Node.js 和原生 Excel 组件
运行环境/Windows-x64/      Windows 10/11 x64 的 Node.js 和原生 Excel 组件
发布配置/Mac/              Mac 启动器和普通用户说明
发布配置/Windows/          Windows 启动器、自检工具和普通用户说明
构建发布程序/              把源码与对应运行环境组合成发布包
用户数据模板/              发布给新用户的空白 JSON
用户数据/                  当前这台 Mac 的真实异常处理进度，不参与打包
发布结果/                  最终生成的两个独立 ZIP

这不是把代码“翻译”两次。两个便携包中的记账规则和网页代码来自同一份“程序源码”；
不同的只是 Node 可执行文件、原生 Excel 组件和双击启动文件。


二、如何在当前 Mac 上使用
------------------------

直接双击项目根目录的“启动记账程序.command”。它会读取：

- 程序源码/
- 运行环境/Mac-x64/
- 用户数据/

当前 Mac 的异常处理进度仍保存在根目录“用户数据”中，不会被构建脚本清空。


三、如何重新生成两个发布包
--------------------------

在终端进入 book_keeping 文件夹，然后运行：

运行环境/Mac-x64/node 构建发布程序/build_releases.mjs

生成结果：

- 发布结果/记账程序-Mac版.zip
- 发布结果/记账程序-Windows版.zip
- 发布结果/发布校验信息.txt

构建脚本只把“用户数据模板”中的空白 JSON 放入 ZIP，不会复制当前 Mac 的真实
“用户数据”，也不会复制程序源码/runs 中的测试任务或任何 .xlsx。


四、应该把哪个文件发给朋友
--------------------------

朋友使用 Windows 10 x64，只发送：

发布结果/记账程序-Windows版.zip

Windows ZIP 不包含 Mac Node、Mac 原生组件或 .command 文件。无需同时发送源码文件夹，
也无需发送 Mac ZIP。


五、朋友出问题时让他发什么
--------------------------

先让朋友双击“检查运行环境.bat”。如果失败，请他发：

- Windows运行环境检查结果.txt
- 启动错误日志.txt（如果存在）

如果是识别规则需要改进，请他在网页导出“规则改进样本.json”。不要让他把整个
程序文件夹或完整流水发回来，除非确实需要复现某个文件结构问题且双方确认隐私风险。


六、版本兼容
------------

Mac 和 Windows 都使用 schemaVersion 1 的异常历史与规则样本格式。两边导出的
“规则改进样本.json”可以交给同一份源码继续改进，不需要按操作系统维护两套规则。
